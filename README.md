# 포트폴리오 사용 안내

흰 배경의 영문 포트폴리오입니다. 소개 → Selected Work → 경력 → 학력 순서이며, 연락처는 소개 안에 표시합니다. KAIST 인턴십은 별도 상세 페이지로 연결됩니다. 기존 세 프로젝트는 본문이 준비될 때까지 펼쳐 읽는 방식을 유지합니다. 편집기에서 설명을 다듬고 이미지나 PDF를 추가할 수 있습니다.

## 가장 쉬운 내용 수정 방법

1. 이 폴더에서 **`편집기-열기.command`를 더블 클릭**합니다. Node.js 22 이상이 필요하며 현재 작업 컴퓨터에는 설치되어 있습니다.
2. 브라우저의 한국어 입력 화면에서 원하는 내용을 영어로 작성합니다.
3. 위쪽 **저장하기**를 누릅니다.
4. **미리보기 ↗**를 열거나 새로고침해 결과를 확인합니다.
5. 다 끝나면 실행된 터미널에서 `Control + C`로 종료합니다.

macOS에서 파일 실행을 막거나 터미널 사용을 원하지 않으면 Codex에 **“portfolio 편집기를 열어줘”**라고 요청하세요. 이미 서버가 실행 중이라면 [편집기](http://127.0.0.1:4173/editor/)로 바로 들어가면 됩니다. 이 주소는 서버가 실행 중인 내 컴퓨터에서만 열립니다.

직접 실행할 때는 이 폴더에서 `npm run dev`를 입력합니다. 별도 패키지 설치는 필요 없습니다. 4173 포트를 이미 사용 중이면 `PORT=4174 npm run dev`로 실행하고 출력된 주소를 사용하세요.

### 입력 규칙

- 이름, 소개, 직함은 자유롭게 바꿀 수 있습니다.
- 자기소개와 긴 설명은 빈 줄로 문단을 나눕니다. HTML이나 Markdown 문법 없이 일반 문장으로 쓰세요.
- 이메일, 소셜 링크, 사진, 이력서는 선택입니다. 비워 두면 링크나 공간이 생기지 않습니다.
- 프로젝트·경력·학력은 **추가**, **삭제**, **위로 / 아래로**로 관리합니다.
- 제목을 지운 항목은 숨겨집니다. 목록을 모두 삭제하면 해당 섹션과 메뉴도 사라집니다.
- 프로젝트 상세 설명을 채우면 **Read project**가 생깁니다. 상세 설명과 역할·기술을 모두 비우면 펼치기 버튼도 사라집니다.
- 프로젝트 이미지는 왼쪽의 동일한 8:5 미리보기 틀에 표시됩니다. 원본을 자르지 않고 틀 안에 맞추며, 클릭하면 원본을 새 탭에서 볼 수 있습니다. 이미지가 없는 프로젝트는 빈 그림 칸 없이 본문이 그 공간을 사용합니다. 모바일에서는 미리보기를 글 위에 배치합니다.
- **프로젝트 PDF**에서 파일을 올리거나 PDF 주소를 넣고, **코드 링크**에 저장소 주소를 넣으면 **PDF · Code** 링크가 설명 아래 나타납니다. 각각 선택 사항입니다.
- 학력은 **학교 → 전공 / 학위 → CGPA·전공 GPA** 순서입니다. 성적은 각각의 입력란에서 바꿀 수 있습니다.
- 이미지는 PNG/JPG/WebP/GIF, 이력서는 PDF로 올릴 수 있습니다. 한 파일은 최대 10 MB입니다.
- 직접 URL을 입력하려면 `https://`부터 입력하세요. 로컬 파일은 `assets/파일명` 형식입니다.
- 자기소개 입력란은 하나입니다. 프로필 사진은 소개 왼쪽에 표시하며 작은 모바일 화면에서는 소개 위쪽에 왼쪽 정렬됩니다.
- 이메일과 소셜 링크는 소개에 표시합니다. 이메일 주소를 클릭하면 복사되고 **Email copied** 안내가 잠시 나타납니다.

### 저장과 배포의 차이

**저장하기**는 내 컴퓨터의 원본과 미리보기를 갱신합니다. 온라인 사이트는 별도로 배포해야 바뀝니다. 방문자가 편집기를 통해 내 파일을 수정할 수는 없습니다. 편집기와 원본 JSON, 백업은 배포 폴더에 포함되지 않습니다.

저장 직전의 내용은 `.local/backups/`에 자동으로 백업됩니다. 잘못 저장했다면 Codex에 **“포트폴리오 내용을 직전 백업으로 복구해줘”**라고 요청할 수 있습니다.

### 인턴십 상세 페이지와 PDF

- 편집기의 **상세 페이지 본문**에서 제목, 설명, 문단, 그림과 캡션을 수정할 수 있습니다. 그림을 교체하면 웹과 PDF에 함께 반영됩니다.
- 프로젝트와 경력의 **연결할 상세 페이지**에서 같은 사례를 선택하면 두 위치가 같은 주소로 연결됩니다. 기관 링크는 별도로 유지됩니다.
- KAIST 주소는 `/projects/kaist-gs1-rag/`이며, `Vector Search`와 `Benchmark`는 하나의 문서 안에 있습니다.
- 상세 페이지의 **Save as PDF**를 누르고 인쇄 대상에서 **PDF로 저장**을 선택하세요. 스크롤 위치와 관계없이 사례 전체가 출력됩니다. 권장 용지는 A4이며, 브라우저 머리글·바닥글은 끄면 됩니다.
- 비교 사례는 웹과 PDF 모두 같은 텍스트를 사용합니다. PDF에서도 진단 문장을 선택하거나 검색할 수 있습니다.
- 상세 본문은 프로젝트 제목 → 섹션 제목 → 필요한 소제목 → 본문 순서입니다. 첫 검색 사례는 첫 번째 섹션 안에 표시됩니다.
- 첫 검색 사례의 **대표 그림**은 선택 항목입니다. 비워도 질문·답·검색 구간과 원본 영상 링크는 표시됩니다.
- 공유할 PDF는 [공개 상세 페이지](https://sunghak222.github.io/projects/kaist-gs1-rag/)에서 저장하세요. 로컬 미리보기에서 인쇄하면 자료 링크가 내 컴퓨터 주소를 가리킵니다.
- 원본은 `content/en.json`의 `caseStudies`에 한 번만 저장합니다. 새 프로젝트 상세 페이지나 섹션을 추가하려면 Codex에 요청하세요. 전체 포트폴리오 PDF는 나머지 상세 페이지가 준비된 뒤 연결할 예정입니다.
- 전달받은 실행 리포트와 원자료는 `.local/kaist-handoff/`에 참고용으로 보관합니다. 웹에는 선별한 그림과 타이밍 CSV만 포함합니다.

## 배포

공개 사이트: **[sunghak222.github.io](https://sunghak222.github.io/)**

원본 저장소: [Sunghak222/sunghak222.github.io](https://github.com/Sunghak222/sunghak222.github.io)

편집기에서 저장하고 미리보기를 확인한 뒤 Codex에 **“portfolio 변경 내용을 GitHub Pages에 배포해줘”**라고 요청하세요. `main` 브랜치에 변경을 올리면 GitHub Actions가 검사·빌드·배포를 자동으로 실행합니다. 로컬 편집기의 저장만으로 온라인 사이트가 바뀌지는 않습니다.

- 배포 설정: `.github/workflows/pages.yml`
- GitHub 설정: **Settings → Pages → Source → GitHub Actions**
- 배포되는 파일: `npm run build`로 생성한 `dist/`의 정적 파일
- `editor/`, 원본 JSON, `.local/backups/`는 웹사이트에 배포되지 않습니다. 다만 저장소는 공개이므로 원본 코드와 `content/en.json`, `public/assets/`는 GitHub에서 볼 수 있습니다.
- 예전 Sites 주소는 이전 버전으로 남아 있으며 앞으로의 배포 대상은 GitHub Pages입니다. `temp.github.io` 저장소와는 별개입니다.

별도 API 키나 유료 호스팅 없이 동작합니다. 나중에 다른 정적 호스팅으로 옮길 때도 `dist/`를 그대로 사용할 수 있습니다.

## 파일 구조

| 파일 / 폴더 | 역할 |
| --- | --- |
| `content/en.json` | 이름, 소개, 프로젝트 등 모든 영문 내용. 편집기가 이 파일을 수정합니다. |
| `public/assets/` | 사진, 프로젝트 이미지, PDF |
| `public/styles.css` | 색상, 여백, 글꼴, 모바일 화면 |
| `scripts/render.mjs` | 페이지 구조와 영문 UI 문구 |
| `scripts/case-studies.mjs` | 상세 페이지 구조와 본문 검증 |
| `public/case-study.css` | 상세 페이지 및 사례 PDF의 인쇄 모양 |
| `public/site.js` | 스크롤 위치에 따른 메뉴 표시 |
| `editor/` | 내 컴퓨터에서만 사용하는 한국어 편집 화면 |
| `dist/` | 자동으로 만들어지는 배포 결과. 직접 수정하지 마세요. |
| `.local/backups/` | 편집 전 자동 백업. 업로드되지 않습니다. |

## 유지보수 메모

- 외부 JavaScript 패키지, 웹폰트, 데이터베이스, API 키가 필요 없습니다.
- 모든 본문은 HTML에 포함되므로 JavaScript가 꺼져도 읽을 수 있습니다.
- 흰 배경으로 고정했습니다. 테마 버튼, 장식용 애니메이션, 채우지 않은 소셜 버튼은 없습니다.
- 나중에 언어 전환을 추가할 때는 `content/ko.json`과 `scripts/render.mjs`의 언어별 UI 문구를 확장하고 언어별 페이지를 생성하면 됩니다. 현재는 영문 페이지 하나만 생성하며 언어 전환은 아직 구현하지 않았습니다.
- `npm test`는 빈 섹션 숨김, 링크 검증, 텍스트 처리, 하위 경로 호환성을 검사합니다.
- `public/sw.min.js`는 같은 주소에서 사용했던 블로그의 오프라인 캐시 연결을 해제하는 호환 파일입니다. 예전 방문자에게 옛 블로그가 계속 보이지 않도록 유지합니다. 현재 포트폴리오는 오프라인 캐시를 등록하지 않습니다.
- 디자인 참고: [Wang Yuqi](https://wangyq.me/en/), [Youngseo Cho](https://cyshello.github.io/portfolio/#/). 원문의 인물 정보·경력·사진은 사용하지 않았습니다.
